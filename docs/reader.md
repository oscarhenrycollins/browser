# Browser Reader (Phase 1)

## Reuse decisions

- **REUSE** `WizardApp` v1 for hosted appearance, live skin changes and Back. The vendored Wizard UI kit and dark tokens are the standalone fallback; they are not a new theme engine.
- **EXTEND** `WizLinks` for outside-link admission to the installed Browser app. Chats and Search use this same implementation. Existing internal routes, file downloads, media handling and explicit system-browser actions remain shared.
- **REUSE / EXTEND** the Browser MCP front and stock Chromium engine. The front retains private `/mcp` and CDP interfaces and adds an explicit public Reader route allowlist. Its single-response relay is shared infrastructure needed for the later front/engine Live implementation, not a Live viewer.
- **NEW** `reader/`: rendering/extraction and proxy policy are Browser app domain code. There is no Search reader and no third-party page iframe inside the Wizard shell.

## Trust boundary

The owner document receives only a JSON article made by **Defuddle 0.19.6** (MIT), with Mozilla Readability 0.6.0 (Apache-2.0) only when Defuddle throws or yields no usable sanitized body, and DOMPurify (Apache-2.0/MPL-2.0), parsed in jsdom without resource loading or script evaluation. Defuddle uses its Node entry point's synchronous `DefuddleClass.parse()` on the server-rendered DOM: `useAsync:false`, a refusing fetch callback, HTML output, and GitHub replies disabled (other discussion extractors retain replies). It never uses third-party API fetching. The existing 50,000-element bound remains. Inside the disposable extraction window only, `reader/fast-select.mjs` answers Defuddle's selector calls: plain tag/class/id/attribute compounds in JS, every other part through jsdom's own `matches()` (skipped for elements that cannot carry its rightmost key), and anything it does not fully understand (`:scope`, namespaces, escapes, legacy case-insensitive attributes without `i`, quirks-mode class/id) unchanged through the engine, with a bounded 64 KiB list allowance because Defuddle's cleanup list exceeds jsdom's 2 KiB default. `test/fast-select.test.mjs` proves identical node sets, `querySelector`, `matches` and `closest` against the engine on every captured corpus page; the sanitizer and Readability are unchanged. Every article text field is rendered as text. Body HTML has a strict element/attribute allowlist. No scripts, handlers, forms, styles, SVG, frames, source CSP/reporting or arbitrary attributes survive. Source pages run only in a disposable remote Chrome context. Source peer sockets, workers, service workers and WebSockets are disabled. A deny-all HTTP proxy is a second fence for any request not explicitly fulfilled through the public-network fetcher.

Each network request resolves all DNS answers, rejects special-use and box-private addresses, pins a checked IP for the connection and rechecks every redirect. Both IPv4 and IPv6 are covered. All single-label service names, localhost variants, local/internal names and Tailscale DNS are blocked. Operators can add public aliases for this box with `READER_DENY_HOSTS` (comma-separated). No request inherits agent or owner cookies, authentication, proxy settings or request headers. Reader never takes the default agent browser context. Reader contexts are closed on completion, error and timeout.

Article requests are limited to two concurrent renders, 25 seconds, 120 resource requests, 8 MiB per resource / rendered DOM and 32 MiB of total response bytes per render. Only GET resources are fulfilled; media/fonts and source WebSockets are refused. Image proxy requests are limited to eight concurrent responses, 15 seconds and 5 MiB, accepting bitmap formats with matching signatures only. SVG/HTML images are not proxied. No pages or cookies are persisted.

The Reader CSP permits only app/Wizard scripts, app styles, same-origin bitmap proxies and same-origin API calls. Its headers include nosniff, same-origin resource policy and no-referrer. Public proxy requests to DevTools or MCP are refused, even while Reader is available. The private network interface remains compatible for existing agent clients.

## When Reader cannot read a page (James, 7 Nov 2026)

`/api/reader` failures return `{error, reason, handoff}`; `reason` is `blocked`, `signin`, `noarticle`, `unavailable`, `private`, `busy` or `invalid` (`reader/handoff.mjs`). The render route classifies the **main document's first response** before Chrome renders it: 401/403/407/429/451, `cf-mitigated: challenge`, small HTML interstitials (Cloudflare "Just a moment…", DataDome captcha, PerimeterX, Incapsula) and redirects to sign-in hosts/paths abort the read at once (about a second, not the 20 s render timeout). Ordinary pages that merely load bot-management scripts are not matched. The body of a refused page never reaches Chrome.

For `handoff:true`, the app clicks a hidden `data-wizard-browse="auto"` anchor so Wizard opens the original immediately (phone: native browser; desktop: only while the owner's tap is fresh, else nothing opens and the visible "Open in your browser" remains). Opened from a link, Reader then returns the owner to where they tapped. Wizard remembers `blocked`/`signin`/`private` hostnames owner-locally to skip Reader for that host next time. `busy`/`invalid` never hand off. Operator logs record only reason and host for these refusals.

Redirects: Chrome is never handed a 3xx. Playwright does not route the request that follows a fulfilled redirect, so before this fix it went to the deny proxy and every redirecting link (http→https, `wikipedia.org`→`en.wikipedia.org`, short links, sign-in walls) failed with `net::ERR_TUNNEL_CONNECTION_FAILED`. Subresources now follow in `safeFetch` (every hop through the destination guard); a main-document redirect aborts and Reader navigates again to the already-checked Location (at most five hops).

The hidden anchor is taken by Wizard's capture-phase link guard with `preventDefault()` **and** `stopPropagation()`, so Reader reads `dispatchEvent()`'s result, never a listener on the anchor itself (gate 7 Nov 2026: the listener never ran, Reader treated every hand-off as declined and stayed open over the chat on phone and desktop).

Read time (James wants Brave-like speed, 7 Nov 2026). Wikipedia/GitHub reads of 5-9 s were not the redirect fix (those pages do not redirect); they were extraction CPU, a fixed 1.2 s wait and image downloads. Now: one jsdom parse instead of two (Defuddle reads the metadata document; Readability, the rare fallback, gets a fresh one); fast exact selectors (above); Chrome gets a 1x1 GIF for images (extraction reads only their attributes, the owner's copy loads each through `api/image`); and the 1.2 s wait ends early once the page's own guarded requests have been quiet for 250 ms (300 ms minimum, 1.2 s maximum; a quiet page with no article yet gets the rest of the old wait once). Per-hop redirect checks and the request/byte budgets are unchanged. The server logs `reader timing <host> {checked,context,loaded,settled,extracted,total}` (milliseconds, host only). Corpus extraction on the VPS, median ms before → after: Wikipedia 4872 → 2363, GitHub README 3168 → 1281, React docs 2773 → 1371, GitHub PR 402 → 350; the extracted articles are byte-identical.

Network/SSRF guard, deny hosts, sanitizer, CSP, edge allowlist and list CSRF are unchanged.
